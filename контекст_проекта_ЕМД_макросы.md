# Контекст проекта: VBA-макросы для таблиц ЕМД (Excel)

## Что это

Набор Excel-файлов (.xlsm) — формы ввода данных по проектам ("ЕМД" —
единая методология данных, видимо). У каждого файла два ключевых листа:
- **главный лист (ЭФ)** — одна строка = один проект, десятки/сотни
  столбцов-атрибутов;
- **лист параметрического представления** (у КЖК называется "КЖК",
  у остальных — "<Система>_ЕМД" или похоже) — реестр метаданных: код
  атрибута, иерархия (декомпозиция по столбцам C:H = уровни 1-6),
  тип по структуре (Простой/Составной), тип по количеству значений
  (ОДИНАРНЫЙ/МНОЖЕСТВЕННЫЙ), код справочника (SPR###), признак
  обязательности.

Задача: по двойному клику на ячейке открывать нужный интерфейс
(справочник, форму подтаблицы, список для множественного атрибута),
без единой кнопки "сохранить" — всё живёт в событиях Excel.

## Архитектура VBA (одинакова во всех файлах, 5 модулей + ЭтаКнига)

- **Module1 (modChildTables)** — "дочерние формы" для одиночных
  атрибутов, открывающих подтаблицу с несколькими записями по
  фиксированному набору столбцов (пример: AKKEMD_024/035 в самом
  первом прототипе "тест1_с_макросами"). В большинстве новых файлов
  — пустая оболочка (`CFG_COUNT = 0`), т.к. все повторяющиеся
  атрибуты теперь идут через Module5.
- **Module2 (modDictionaries)** — работа со справочниками SPR###:
  `Dict_OpenFromMain` / `Dict_OpenFromRow` (открыть, с параметром
  строки, где лежит код — либо `DICT_CODE_ROW` на главном листе,
  либо строка 3 на листе-рыбе множественного атрибута),
  `Dict_SelectFromDictionary` (выбор значения), `GetDictConfig`
  (спец-настройки для отдельных SPR-кодов: составные значения из
  нескольких столбцов через " / ", фильтрация и т.п. — например
  SPR039 (страны) берёт название, а не буквенный код). Справочник
  открывается `ReadOnly`, листы защищены (`UserInterfaceOnly`, без
  пароля) — видимым остаётся только нужный лист SPR###
  (`ShowOnlySprSheet`).
  **Этот модуль одинаковый во всех файлах, копируется как есть.**
- **Module3 (modRouter)** — единая точка входа:
  `Router_DoubleClick` (диспетчеризация двойного клика) и
  `Router_SheetChange` (на изменение ячейки — нужно для
  автостирания записей в Module5). Константы **у каждого файла
  свои**: `MAIN_SHEET_NAME`, `ATTR_CODE_ROW`, `DICT_CODE_ROW`,
  `FIRST_INPUT_ROW`, `PROJECT_ID_COL` (см. таблицу ниже).
  Также здесь `ValidateRequiredFields` (полная проверка ~29
  обязательных полей, СЕЙЧАС НЕ подключена к сохранению) и
  свежедобавленная `ValidateEntryDateRequired` (только "Дата
  ввода", столбец A — подключена к `Workbook_BeforeSave`).
- **Module4 (modMultiAttr)** — "старая" система множественных
  атрибутов без сводной ячейки (несколько отдельных
  столбцов-триггеров на одну группу). Почти везде теперь пустая
  оболочка (`CFG_COUNT = 0`) — оставлена только чтобы Module3
  компилировался без правок, если понадобится вернуть.
- **Module5 (modNestedGroups)** — ОСНОВНАЯ логика множественных
  атрибутов. Смотри раздел ниже.
- **ЭтаКнига (ThisWorkbook)** — `Private WithEvents App As
  Application`; `Workbook_Open`/`InitEvents` (подключение событий +
  `ReapplyGroupProtection`, т.к. `UserInterfaceOnly`-защита не
  сохраняется между сеансами Excel); `App_SheetBeforeDoubleClick` →
  `Router_DoubleClick`; `App_SheetChange` → `Router_SheetChange`;
  `Workbook_BeforeSave` → `ValidateEntryDateRequired`.
  Строка `Application.OnDoubleClick = vbNullString` (сброс старого
  механизма) обёрнута в `On Error Resume Next` — у Application нет
  гарантированной поддержки этого свойства, падало с 1004.

## Module5 — система вложенных групп (ключевое)

Тип `TGroup` на каждую группу-атрибут:
```
GroupCode, ParentSheetName, ParentCol, ParentKeyCol,
SheetName, TitleText, LastCol, ValueCols, KeyCol, CtxCol,
Headers, Widths, IntCols, MoneyCols, DictCodes,
ChildGroupCode, ChildSummaryCol
```
`LoadGroupCfg(Index, Cfg)` — один `Select Case` на все группы файла
(`GROUP_COUNT` в начале модуля).

**Логика:**
- На главном листе — ОДНА ячейка-сводка на группу (не отдельные
  столбцы под каждое поле). Код группы лежит в этой ячейке в
  строке `ATTR_CODE_ROW`/`MULTI_ATTR_CODE_ROW`. Она НЕ
  редактируется руками — в ней автоматически появляется
  "Заполнен N атрибутами" после первого заполнения записи.
  Двойной клик по ней → `Group_OpenFromMain` → открывает лист
  группы (строится автоматически при первом обращении, скрыт).
- Если у группы есть вложенная (пример: KJKEMD_032 → KJKEMD_176,
  KJKEMD_087 → KJKEMD_112) — внутри листа родителя есть СВОЯ
  сводная ячейка (`ChildSummaryCol`), по одной НА КАЖДУЮ строку
  (т.к. у каждой строки родителя — например, у каждого учредителя —
  свой независимый список). Для этого у родителя есть скрытый
  столбец `KeyCol` с УНИКАЛЬНЫМ ключом записи (генерируется через
  счётчик в ячейке `BZ1` листа, формат `K000001`, никогда не
  переиспользуется). Вложенный лист хранит в своём столбце A не
  ID проекта, а этот ключ (`ParentKeyCol`).
- `CtxCol` — скрытый столбец на листе группы, 4 ячейки: 1=текущий
  ключ, 2=строка возврата у родителя, 3=ID проекта (для
  отображения), 4=имя листа-родителя (куда возвращаться).
- Кнопки A2/B2 на каждом листе группы: "Добавить запись" /
  "Вернуться на форму" (`Group_HandleClick`).
- При возврате (`ReturnFromGroup`): `PurgeEmptyRows` (см. ниже) →
  `ValidateGroupRows` (если строка начата — все поля ValueCols
  обязательны, иначе не даёт вернуться) → скрыть лист →
  `RefreshSummaryForKey` (пересчитать и записать "Заполнен N
  атрибутами" в ячейку родителя, ищет через `Find` по
  ID-проекта/ParentKeyCol).
- `PurgeEmptyRows` (добавлено недавно) — при возврате чистит
  строки, где заполнен только ключ (столбец A, поставленный
  автоматически при открытии), а ни одно поле ValueCols не
  тронуто — такая "пустышка" не должна считаться записью.
- `NestedGroup_HandleChange`/`HandleGroupSheetChange` — событие
  изменения ячейки на листе группы: если строка, где раньше было
  что-то заполнено, стала полностью пустой (по ValueCols) —
  стереть ключ (и каскадно стереть вложенные записи через
  `ClearChildGroupRecords`, если у этой группы есть дочерняя);
  если писали в пустую строку без ключа — подставить ключ
  автоматически. Физическая строка листа НЕ удаляется (чтобы не
  сломать автофильтр) — только очищается.
- Справочники (SPR###) внутри листа группы: код лежит в строке 3
  (`DICT_CODE_ROW_CHILD`), скрытой; открывается через
  `Dict_OpenFromRow(ws, Cell, 3)` из Module3.
- Защита листов группы: `ProtectGroupSheet` — `UserInterfaceOnly`,
  без пароля; заблокированы служебные столбцы (A, KeyCol,
  ChildSummaryCol, CtxCol), разблокированы ValueCols и кнопки A2:B2.
  **ВАЖНО**: при установке Locked нельзя трогать строку 1 (там
  объединённая ячейка заголовка A1:LastCol1) — иначе ошибка "Нельзя
  установить свойство Locked класса Range". Работаем со строки 2.

## Известные баги, которые уже чинили (чтобы не наступить повторно)

1. **`ws.Columns("A").Locked = True`** ломается на строке 1 (см.
   выше про merge) — использовать `ws.Range("A2:A10000").Locked`.
2. **`EnsureFirstGroupRecord`** должна принимать `Cfg As TGroup` по
   ссылке (вызывает `FormatGroupRow`, которой нужен `Cfg`) —
   однажды забыл параметр, дало "Variable not defined".
3. **`Array(...)` с более чем ~24 элементами через `_`** — у VBA
   жёсткий лимит 24 продолжения строки на оператор ("Too many line
   continuations"). Длинные списки (`RequiredColumns`, 29 полей)
   собирать через 2D-массив с построчным присвоением
   (`Result(i,1) = Array(...): i = i + 1`), а не одним литералом.
4. **Копипаста больших модулей в редактор VBA иногда роняет
   Excel** (Module5 ~950 строк) — использовать **File → Import
   File**, а не Ctrl+V, это читает с диска и не падает.
5. **"Attribute App.VB_VarHelpID = -1"** — это компилятор сам
   генерирует для `WithEvents`-переменных, руками её вписывать
   нельзя (Syntax error). Если видите её при копипасте кода — не
   переносите, VBA добавит сама.
6. **Кириллица в именах файлов внутри zip** — Windows не видит
   кодировку, показывает кракозябры. Собирать zip через Python
   `zipfile` с явным `zi.flag_bits |= 0x800` (UTF-8 флаг).
7. **"Object library invalid..." при компиляции** — это про
   Tools → References, не про код модулей; искать строку с
   пометкой MISSING и снимать галочку.
8. Значения обратно в главную ячейку не должны попадать "код вместо
   названия" — проверяйте `GetDictConfig` в Module2 для каждого
   нового SPR-кода (пример: SPR039 — страны, брать колонку с
   названием (F), не с буквенным ISO-кодом (C)).

## Что осталось не сделано / требует внимания

- **IntCols/MoneyCols** (формат "целое"/"деньги, 2 знака") НЕ
  расставлены для групп в АКК СХ/ДАМУ/Лизинг/ЭКА (только в КЖК
  сделано вручную по смыслу названий) — можно доразметить по
  необходимости прямо в `LoadGroupCfg` каждого файла.
- **Лизинг**: на листе "Лист2" (=ЭФ_Лизинг) уже был СВОЙ старый
  механизм открытия справочника с захардкоженным путём под чужой
  компьютер (`C:\Users\A2DATA\...`) — конфликтует с новой системой,
  надо снести `Worksheet_BeforeDoubleClick` в этом листе перед
  установкой новых модулей.
- **Лизинг и ЭКА**: в старых Module2 (Лизинг) / Module4 (ЭКА) была
  утилита `Sub ПРОПИСНЫЕ()` — наши новые модули с теми же именами
  её затирают, надо было перенести перед заменой (могло быть уже
  сделано или потеряно — не проверял позже).
- **ЭКА**: старый Module3 до правки имел неверные константы
  (`ATTR_CODE_ROW=8`, `PROJECT_ID_COL="C"` вместо правильных 7 и
  "D") — новый Module3 это чинит.
- **`ValidateRequiredFields`** (полный список ~29 обязательных
  полей на главном листе КЖК) написана, но НЕ подключена к
  `Workbook_BeforeSave` (пользователь просил отключить временно).
  Часть из этих 29 полей выглядит условно обязательной (жильё-блок
  Q-V, код страны для нерезидента Z) — не проверял условную логику.
- **KJKEMD_176 / KJKEMD_112** (и вложенные группы в остальных
  файлах) — вложенность реализована ПРАВИЛЬНО, ключ у каждой
  родительской строки свой (не путать с более ранней версией в
  этом диалоге, где вложенность сперва была "плоской", т.е. одна на
  весь проект — это исправлено).
- Файлы АКК СХ (01 и 23) — по сути одинаковый шаблон, коды/вложенность
  идентичны, но 01 использует `PROJECT_ID_COL="C"` (упрощённая
  структура без отдельного столбца "ID Заявки"), а 23 — "D".

## Стиль/соглашения, которых стоит придерживаться дальше

- Все листы групп строятся программно (`BuildGroupSheet`) при
  первом обращении — не создавать их вручную в Excel.
  Если структура листа группы меняется (новые поля) — старый лист
  НЕ пересобирается автоматически, нужно удалить его вручную,
  чтобы макрос пересоздал с нуля (или писать отдельную функцию
  миграции, если на листе уже есть реальные данные).
- Названия столбцов/заголовков берутся из листа параметрического
  представления (`J` — текстовая композиция, `P` — код SPR) —
  не выдумывать вручную, тянуть из реестра.
- Все правки модулей отдаю пользователю как отдельные .bas/.cls
  файлы (или .txt по её последней просьбе) — вставлять через
  **File → Import File** в VBA-редакторе, не копипастой, кроме
  ЭтаКнига (объектный модуль книги, всегда только копипаста).
